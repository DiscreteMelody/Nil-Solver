# Thirteen-card deals with a bid on each side that a PLAYER WOULD ACTUALLY MAKE.
# Contributed by T from the table, not generated.
#
# WHY THIS FILE EXISTS SEPARATELY FROM opposed13.txt.  That corpus is eight
# CONTESTED deals, selected because both bids are live and the search is hard.
# Selecting for difficulty selects against structure, and several measurements
# have now come back empty on it for that reason alone -- patch 89's static
# doom check fired on 0 of 8, and patch 91's reachability bound narrowed the
# rank band on 0 of 8.  Neither result says the idea is worthless; both say the
# corpus cannot see it.
#
# It also does not exercise the OUTCOMES.  Every deal in opposed13.txt ends
# (fail, fail).  A presolve whose whole job is to bound the outcome rank was
# being measured against a corpus that only ever reaches one rung of the ladder.
# The two rows here are the other outcomes:
#
#   r13-0000   (fail, make)   one bid set while the other survives -- rank 3 for
#                             the surviving side, the conjunction outcome that
#                             item 78's probe exists to detect
#   r13-0001   (make, make)   both bids survive -- the outcome item 60's 2/2
#                             rule names and patch 90's probe guards
#
# Format is the shared corpus one, so leader and seats travel WITH each row
# rather than as command-line flags:
#
#   name | pbn | leader | seats | broken | trick | secondary |
#   nils_set | nil_tricks | side_tricks | pv | provenance
#
# `nil_tricks` is the two bidders' COMBINED trick count and `side_tricks` is
# the first-named side's, which is the reading the CLI's compact output uses.
# Both columns name "the nil bidder" in their titles and cannot really describe
# a deal with two; multinil.txt records the same complaint.  Left as-is here so
# one reader serves every corpus.
#
# Provenance is `solver`: these are pinned from this solver, which is a weaker
# claim than an oracle row -- it says the answer has not CHANGED, not that it is
# right.  At thirteen cards the oracle cannot check them in reasonable time.
# What raises them above a bare pin is that T stated each deal's outcome BEFORE
# it was run and the solver agreed, so the outcome column has an independent
# witness even though the trick counts do not.
#
# Run:
#   nil_bench --corpus tests/corpus/opposed13_real.txt --mode full
#
# These are slow -- roughly 159M and 13M nodes -- so they are a bench anchor and
# not a ctest fixture.
